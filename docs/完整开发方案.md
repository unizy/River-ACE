# 网页版德州扑克完整开发方案

## 一、产品定位

项目名称暂定：《River Ace》

产品形态：

- 浏览器直接打开
- PC 和手机均可游玩
- 无需安装
- 支持安装为 PWA
- 使用虚拟筹码
- 不涉及现金、充值或真实赌博
- 第一版为玩家对战电脑
- 后续扩展好友房和在线匹配

推荐第一版参数：

- 无限注德州扑克
- 2～10 人牌桌
- 默认 1 名玩家＋3 名电脑
- 每位玩家初始 2000 筹码
- 小盲注 10，大盲注 20
- 固定盲注现金桌模式
- 电脑玩家破产后自动补充筹码
- 玩家破产时可以重新开始

## 三、游戏规则范围

第一版严格实现无限注德州扑克。

### 牌局位置

每局庄家按钮顺时针移动。

庄家左侧依次为：

1. 小盲注
2. 大盲注
3. 枪口位及其他位置

两人牌桌采用单挑规则：

- 庄家支付小盲注
- 另一名玩家支付大盲注
- 翻牌前庄家先行动
- 翻牌后大盲注玩家先行动

### 发牌流程

1. 重置本局下注数据
2. 移动庄家按钮
3. 收取小盲注和大盲注
4. 每位有效玩家获得两张底牌
5. 进入翻牌前下注
6. 发出三张翻牌
7. 进入翻牌下注
8. 发出一张转牌
9. 进入转牌下注
10. 发出一张河牌
11. 进入河牌下注
12. 摊牌并结算底池

数字游戏可以不显示烧牌，但规则引擎内部可以在每次发公共牌前移除一张牌，以保持与实体流程一致。

### 玩家操作

玩家可以执行：

- `fold`：弃牌
- `check`：过牌
- `call`：跟注
- `bet`：首次下注
- `raise`：加注
- `allIn`：全下

界面只显示当前合法操作。

例如前面已经有人下注时，不显示“下注”，而显示：

- 弃牌
- 跟注
- 加注
- 全下

### 最低加注

系统记录：

- 当前最高下注
- 上一次完整加注幅度
- 玩家本轮已投入筹码
- 玩家是否已行动
- 玩家是否仍有加注权

例子：

- 大盲注 20
- 玩家加注到 60
- 完整加注幅度为 40
- 下一名玩家若正常加注，至少需要加到 100

不足完整加注幅度的短码全下可以成立，但不会自动重新开放已经行动玩家的加注权。

### 提前结束

任意下注阶段只剩一名未弃牌玩家时：

- 不再发剩余公共牌
- 该玩家立即获得所有底池
- 不公开底牌
- 进入下一局

## 四、牌型判断方案

每位玩家最多有七张可用牌：

- 两张底牌
- 五张公共牌

规则引擎从七张牌中枚举所有五张组合，共 21 种，找出最大的组合。

第一版采用这种方案，代码简单可靠，性能完全足够。

牌型编码：

编码

牌型

8

同花顺

7

四条

6

葫芦

5

同花

4

顺子

3

三条

2

两对

1

一对

0

高牌

每个结果生成可直接比较的数组。

例如：

```
四条 A，踢脚 K
[7, 14, 13]

两对 A 和 10，踢脚 8
[2, 14, 10, 8]

一对 Q，踢脚 A、9、7
[1, 12, 14, 9, 7]
```

特殊处理：

```
A、2、3、4、5
```

视为五高顺子，而不是 A 高顺子。

花色没有大小关系。

### 公共牌成牌

允许最佳牌型完全由五张公共牌组成。

如果多名玩家最佳五张牌完全相同：

- 平分对应底池
- 不使用第六张或第七张牌决胜

无法平均分配的零头筹码，交给庄家左侧顺时针方向最先出现的获胜者。

***

## 五、主池与边池

每名玩家记录本局累计投入。

结算时：

1. 收集所有不同的投入层级。
2. 按层级拆分底池。
3. 每个底池记录有资格争夺的玩家。
4. 弃牌玩家投入的筹码保留在底池中，但没有获胜资格。
5. 每个底池分别比较牌型。
6. 平局时分别平分。

示例：

```
玩家 A 全下 100
玩家 B 投入 300
玩家 C 投入 500
```

形成：

```
主池：100 × 3 = 300
A、B、C 均可争夺

第一边池：(300 - 100) × 2 = 400
B、C 可以争夺

第二边池：500 - 300 = 200
只有 C 符合资格，直接退还或归入其不可争议筹码
```

## 六、电脑玩家设计

电脑不得读取其他玩家底牌，也不能根据牌堆未来顺序决策。

### 决策输入

电脑只能获得：

- 自己的两张底牌
- 已公开的公共牌
- 当前底池
- 跟注金额
- 有效筹码
- 玩家数量
- 对手历史行动
- 自己的位置
- 当前下注阶段

### 翻牌前判断

第一版使用起手牌评分表，考虑：

- 对子
- 高牌
- 同花
- 连张
- 位置
- 有效筹码
- 前面加注次数

可将起手牌划分为：

- 顶级牌
- 强牌
- 可玩牌
- 投机牌
- 弱牌

### 翻牌后判断

采用胜率估算：

1. 收集所有未知牌。
2. 随机生成对手可能底牌。
3. 随机补齐尚未出现的公共牌。
4. 重复模拟数百次。
5. 得到获胜、平局和失败比例。
6. 与底池赔率比较。

基础公式：

```
跟注所需胜率 = 跟注金额 ÷ 跟注后的总底池
```

如果估算胜率明显高于所需胜率，电脑倾向跟注或加注。

计算可以放进 Web Worker，避免界面卡顿。

### 电脑性格

第一版设置四类：

性格

特点

谨慎型

起手牌范围窄，较少诈唬

激进型

经常下注和加注

跟注型

很少加注，但喜欢跟注

均衡型

根据位置、胜率和底池赔率行动

性格只影响：

- 起手牌范围
- 加注频率
- 诈唬概率
- 下注尺度
- 面对加注时的弃牌倾向

不能通过性格获得隐藏信息。

### 下注尺度

电脑从以下尺度中选择：

- 1/3 底池
- 1/2 底池
- 2/3 底池
- 3/4 底池
- 满池
- 全下

避免生成大量没有战略意义的随机筹码数字。

## 七、页面结构

第一版采用单页游戏结构。

### 顶部区域

包含：

- 游戏名称
- 当前盲注
- 局数
- 设置按钮
- 新牌局按钮
- 音效开关

### 中央牌桌

使用椭圆形深绿色桌面。

桌面中央显示：

- 五张公共牌
- 主池金额
- 边池金额
- 当前阶段
- 庄家按钮
- 最近一次操作

玩家座位显示：

- 名称
- 头像或阵营标志
- 剩余筹码
- 本轮下注
- 两张牌
- 当前状态
- 庄家、大小盲标记

电脑底牌默认背面显示；摊牌时只公开仍有资格争夺底池的牌。

### 玩家操作区

页面底部固定显示：

- 弃牌
- 过牌或跟注
- 加注
- 全下
- 加注滑块
- 最小、半池、满池、全下快捷按钮

同时显示：

- 跟注需要多少筹码
- 当前底池
- 自己本局已投入多少
- 当前可下注范围

### 对局日志

桌面右侧或手机抽屉中显示：

```
玩家 2 支付小盲注 10
玩家 3 支付大盲注 20
你跟注 20
玩家 2 加注到 80
你弃牌
玩家 2 获得底池 140
```

### 摊牌结果

结算时显示：

- 获胜玩家
- 最佳五张牌
- 牌型名称
- 获得的底池
- 主池与边池分配
- 下一局倒计时

***

## 八、视觉设计

整体风格：

- 深绿色绒布牌桌
- 深色背景
- 暗金色边框
- 胡桃木或黑色桌沿
- 白色扑克牌
- 红黑双色花色
- 少量蓝色用于操作提示

不使用赌场广告式霓虹效果，整体偏沉稳、清晰。

扑克牌第一版使用 CSS 和文字绘制，不依赖外部卡牌图片：

```
A♠
10♥
K♦
7♣
```

优势：

- 加载快
- 清晰度不受屏幕影响
- 容易适配手机
- 不存在素材版权问题

动画包括：

- 发牌滑入
- 翻牌
- 筹码移入底池
- 获胜筹码移向玩家
- 当前行动玩家高亮
- 全下状态强调

### 桌面端

- 椭圆牌桌占据中央
- 最多十个座位围绕牌桌
- 日志显示在右侧
- 操作栏位于底部

### 手机端

- 优先支持竖屏
- 玩家座位缩小为头像和筹码
- 公共牌保持完整显示

```

→ DEALING
→ PREFLOP
→ FLOP
→ TURN
→ RIVER
→ SHOWDOWN
→ SETTLEMENT

```

任何界面按钮都不能直接修改筹码或牌局，只能提交一个动作给规则引擎。

规则引擎负责：

1. 检查动作是否合法。
2. 修改游戏状态。
3. 寻找下一位玩家。
4. 判断下注轮是否结束。
5. 判断是否进入下一阶段。
6. 判断是否提前结束。
7. 生成操作日志。

## 十一、随机与公平性

实际游戏洗牌使用浏览器安全随机数：

```
crypto.getRandomValues
```

测试环境使用可指定种子的伪随机数，以便复现问题。

单机版中：

- 所有牌只生成一次
- 电脑不能读取对手底牌
- AI 模块只接收经过过滤的可见状态
- 调试信息在正式构建中关闭

未来在线版中：

- 洗牌必须在服务器完成
- 浏览器不能决定牌面
- 浏览器只能提交操作
- 服务器验证所有筹码和行动
- 对手只接收自己有权看到的信息

***

## 十二、本地存储

第一版无需账号。

使用浏览器保存：

- 音效设置
- 默认玩家数量
- 电脑难度
- 总局数
- 胜利次数
- 最大底池
- 盈亏统计
- 最近牌局记录

设置可以放在 `localStorage`。

完整手牌历史如果数量较多，使用 IndexedDB。

提供：

- 清空统计
- 删除牌局记录
- 导出文本记录

## 十三、测试计划

### 牌型测试

覆盖：

- 所有十类牌型
- A2345 顺子
- 皇家同花顺
- 公共牌直接构成最佳牌
- 两名玩家完全平局
- 同花逐张比较
- 葫芦先比较三条
- 两对比较和踢脚
- 七张牌存在多种组合时选择最佳五张

### 下注测试

覆盖：

- 大小盲不足时全下
- 最低加注
- 短码全下
- 短码全下不重新开放加注权
- 所有玩家过牌
- 加注后重新轮转
- 只剩一人时立即结束
- 所有剩余玩家全下时自动发完公共牌

### 底池测试

覆盖：

- 单一底池
- 一个边池
- 多个边池
- 弃牌玩家贡献筹码
- 主池与边池由不同玩家获胜
- 边池平分
- 零头筹码分配

### 稳定性测试

至少自动运行数万局随机电脑对战，检查：

- 一副牌中没有重复牌
- 筹码总额守恒
- 不会卡在某个玩家
- 不会出现负数筹码
- 弃牌玩家不能获胜
- 没有资格的玩家不能获得边池
- 每局最终一定能够结束

## 十五、验收标准

第一版完成时，应满足：

1. 玩家可以连续进行多局游戏。
2. 支持 2～10 人牌桌。
3. 所有德州扑克牌型判断正确。
4. 所有合法操作根据牌局状态动态显示。
5. 支持弃牌、跟注、过牌、下注、加注和全下。
6. 支持一个或多个边池。
7. 电脑不会读取隐藏牌。
8. 手机和桌面均可操作。
9. 刷新后可以保留设置和统计。
10. 没有重复发牌、负筹码或筹码凭空增减。
11. 可以从对局日志复原本局主要过程。
12. 网页首次打开即可开始，不要求注册。

***

## 十六、最终推荐路线

优先完成：

```
纯 TypeScript 规则引擎
→ 自动化测试
→ React 牌桌界面
→ 基础电脑玩家
→ 完整边池与结算
→ 动画和音效
→ 手机适配
→ PWA
```

不要先做登录、商城或在线匹配。

这款游戏最大的开发风险不是画面，而是：

- 加注轮转
- 短码全下
- 边池
- 平局
- 两人桌行动顺序
- AI 偷看隐藏信息

因此必须先完成独立且可测试的规则引擎，再制作正式界面。
